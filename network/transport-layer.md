# 전송 계층 — 연결은 왜 비싼가

## 30초 요약

- TCP 연결 수립은 **왕복 1.5회**(3-way handshake)다. TLS를 얹으면 왕복이 1~2회 더 붙는다
- 서버가 멀면 왕복 한 번이 수십 ms다 → **요청마다 연결을 새로 맺으면 데이터를 보내기도 전에 100ms를 쓴다**
- 그래서 연결을 재사용한다 — **HTTP Keep-Alive**와 **커넥션 풀**은 같은 문제의 두 해법이다
- 재사용에는 함정이 있다. **서버가 먼저 끊은 연결을 클라이언트가 모르고 쓰면 에러**다 → `maxLifetime`을 서버 idle timeout보다 짧게
- TCP는 **연결·순서·재전송을 보장**하고 UDP는 안 한다. 그 보장의 대가가 위의 왕복 비용이다

---

## 원리 — 왜 그런가

### 2-1. TCP — 커넥션 풀이 왜 필요한가

**연결을 맺는 데 왕복이 필요하다.**
```
3-way handshake:  SYN → SYN-ACK → ACK    (왕복 1.5회)
TLS 협상 추가하면:                        (왕복 1~2회 더)
```
서버가 멀면 왕복 한 번에 수십 ms다. **요청마다 이걸 내면 실제 데이터를 보내기도 전에 100ms를 쓴다.**

**→ 그래서 연결을 재사용한다.**
- **HTTP Keep-Alive**: 응답 후에도 연결을 끊지 않고 다음 요청에 재사용
- **커넥션 풀**: 미리 만들어 두고 빌려 쓴다 (DB도, HTTP 클라이언트도 같은 원리 → [트랜잭션 · 락](../database/basics/transaction-and-lock.md) §2-10)

**⚠️ 커넥션 풀의 함정**: 서버 쪽이 먼저 연결을 끊었는데 클라이언트가 모르고 그 커넥션을 쓰면 에러가 난다. → **`maxLifetime`을 서버의 idle timeout보다 짧게** 잡는다.

**TCP vs UDP** (한 줄 정리): TCP는 **연결·순서·재전송 보장**, UDP는 없다. 대신 UDP가 가볍다.
